Política de privacidad

Esta política distingue el tratamiento actual del sitio y las pruebas de desarrollo de SERESTA de las operaciones que solo se contemplan para una futura puesta en producción.

1. Quién presenta esta política y alcance

Johan Felipe Pabon Garcia, persona natural, es el titular del sitio y desarrolla y presenta SERESTA bajo la marca iQFeeDex. Sus datos de identificación y contacto están disponibles en el aviso legal. Para consultas sobre esta política puedes escribir a jfelipepabong@gmail.com. Los roles de protección de datos de iQFeeDex y de cada negocio deberán precisarse antes de ofrecer SERESTA a clientes o iniciar un piloto.

Esta política aplica al sitio informativo y describe por separado el estado actual del prototipo y el tratamiento previsto del producto. SERESTA está en desarrollo; actualmente no procesa datos reales de clientes en producción.

2. Datos tratados actualmente

Este sitio no tiene formularios, cuentas de usuario, comentarios ni analítica propia, y no envía los datos que introduces en otros servicios a una base de datos de iQFeeDex. El alojamiento web puede procesar datos técnicos de solicitudes —por ejemplo, dirección IP, fecha, navegador y datos de conexión— para servir el sitio y protegerlo, de acuerdo con la configuración y las políticas de Cloudflare.

Los enlaces de correo, teléfono y WhatsApp abren servicios externos. Si decides contactarnos, esos proveedores procesarán los datos que compartas para cursar la comunicación. El mensaje sugerido en WhatsApp no se envía hasta que tú lo confirmes.

El prototipo técnico local de SERESTA se prueba con datos sintéticos. Guarda identificadores únicos de mensajes en una base D1 local para evitar duplicados; según el estado actual informado, no guarda el contenido de los mensajes ni datos de contacto y no recibe datos reales de clientes.

3. Datos que SERESTA podría tratar

Si el producto se implementa y se pone en operación, se prevé tratar solo lo necesario para gestionar una solicitud o cita: número o identificador de WhatsApp; nombre, si la persona lo proporciona; mensajes pertinentes a su solicitud; local, servicio y trabajador elegidos; disponibilidad consultada; y fecha, hora y estado de la cita. También se tratarían datos de configuración del negocio y la autorización del propietario para consultar su Google Calendar.

Estos datos se usarían para entender la solicitud, identificar el negocio y servicio, consultar disponibilidad, responder al cliente y crear o cancelar una cita después de la confirmación correspondiente. No se planea usar esos datos para publicidad ni venderlos.

Esta descripción es del diseño previsto, no de una función activa. Antes de un piloto se informarán los datos, finalidades y condiciones reales, y se obtendrán las autorizaciones que correspondan.

4. Almacenamiento y proveedores

El prototipo actual funciona localmente y utiliza datos sintéticos; los identificadores de mensajes de prueba se guardan en una base D1 local únicamente para deduplicación. La arquitectura planeada para el servicio contempla Cloudflare Workers y D1 para procesar y almacenar datos operativos, y Google Calendar para guardar citas en el calendario que autorice cada propietario. Esta arquitectura aún no está desplegada para recibir datos reales y la configuración final está pendiente.

La operación futura podría involucrar a WhatsApp/Meta y Google como proveedores de los servicios necesarios para la comunicación y el calendario. Cada proveedor trataría datos conforme a sus propios términos y políticas. La ubicación, transferencias, acuerdos y configuración finales deberán definirse antes de producción.

5. Acceso, seguridad y conservación

En el flujo previsto, el cliente se comunicaría con el número de SERESTA; el propietario administraría los datos de configuración de su negocio y el calendario que autorice. Los roles del equipo de SERESTA y los controles de acceso internos aún deben definirse antes de cualquier piloto.

En el prototipo se han implementado comprobación del desafío de suscripción del webhook, validación de la firma HMAC-SHA256 de notificaciones y deduplicación por identificador de mensaje. Son pruebas locales con datos sintéticos y no deben interpretarse como controles de producción. Antes de operar con datos reales quedan pendientes, entre otros, el aislamiento de datos entre negocios, la gestión segura de credenciales y tokens, los permisos, y los procesos de conservación y eliminación.

El plazo de retención definitivo todavía no está establecido. Se publicará antes de iniciar un piloto o producción; no afirmamos que haya ya un procedimiento de borrado operativo para el producto.

6. Derechos y solicitudes

Para consultar, actualizar, corregir o solicitar la eliminación de información personal que nos hayas compartido directamente, escribe a jfelipepabong@gmail.com e indica tu solicitud. Cuando SERESTA esté operativo, se informará el canal y el procedimiento para consultar, actualizar, corregir o solicitar la eliminación de datos, así como las condiciones aplicables para atender estos derechos. La información que trate un proveedor externo puede requerir también una solicitud a dicho proveedor.
